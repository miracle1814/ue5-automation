## 一、你三个问题的落地答案

**Q1：升级后的官方 MCP 支持全系列吗？**
不能。官方 `ModelContextProtocol` 插件只随 UE 5.8 引擎提供（已核实 5.1 引擎内无此插件、无 ToolsetRegistry，且不现实回植）。**但通过反向融合拿到了全系列**：把 MCP 协议做进你的 skill —— 5.1–5.5 编辑器自带 `/mcp` 端点，任何 MCP 客户端可直连；5.8 走官方 MCP + 本包交付的工具集插件。

**Q2：把 MCP 优点升进 skill，升了哪些？**
① MCP 协议接入层（`/mcp`，零依赖手写，UE5.1 内嵌 Python 3.9 装不了官方 SDK）；② PIE 运行时验证族（官方"读运行时状态证明行为"范式）；③ Actor 查改族（含传送回读比对）；④ 日志自取（`logs_read` 游标增量）；⑤ 命令批量（`editor_batch`，把多次往返压成一次）。

**Q3：合并成一个工具？**
最终形态 = **一个能力核心 × 两种协议外壳**：C++ 桥 + ue5_bridge 中层是唯一能力实现（PIE/日志/Actor/批量只写一遍）；5.1–5.5 经自建 `/mcp` 或原 HTTP 端点访问，5.8 经官方 MCP + `ue5-automation-extras` 工具集（进程内直调，零重复实现）。没有"把两个工具合成一个新单体"——官方插件是引擎的一部分，只能被挂载。

## 四、环境层面的关键发现（供后续排障，均已记录进 BUILD.md / 报告）

1. **SKILL.md 旧记载"VS 2022 14.42"有误**：团队历史上的成功编译实际用的是 **VS2019 BuildTools 14.29**（本机 `C:\Program Files (x86)\Microsoft Visual Studio\2019\BuildTools`，与插件侧 BuildConfiguration.xml 的 `CompilerVersion=14.29.30133` 一致）。本轮已把全局 UBT 配置恢复为 `VisualStudio2019`。
2. **UE5.1 的旧 UBT 在本机（Win11 26100）存在 998 崩溃**（`ManagedProcessGroup.get_TotalProcessorTime` 访问无效内存）：**仅在"内存限流到 1 进程"路径触发**；恢复并行（≥5 进程）后正常。附带的教训：低内存时 UBT 限流易踩雷 → 编译前保证 ≥1.5GB free/action。
3. **UE 5.8 编译被工具链封禁**：5.8 的 UBT 明令封禁 MSVC 14.40–14.43（本机 14.42 在列），需装 14.50+。**这是 5.8 侧 C++ 桥唯一阻塞项**——源码与一键脚本已随包，装好工具链后 `build_for_engine.bat "开发机 UE 5.8"` 即可补齐。
4. **Windows 回收站/强杀副作用**：强杀编辑器会弹"恢复包"模态框阻塞远程执行（本轮用桌面自动化点了"跳过恢复"）；未来验证流程建议先 `quit` 或接受对话框处理步骤。
