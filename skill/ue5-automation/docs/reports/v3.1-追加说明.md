## 一、取舍#6 落地：写操作回读比对覆盖补满

**新机制**：
- **UMG 设属性**：C++ 新增 `ReadWidgetProperty`（导出属性文本）→ `widget_set_property` 设置后**强制回读比对**，
  不一致即 fail-loud；返回体新增 `readback` / `verified` / `applied_value`。
- **材质设属性**：Python 侧由"只回传"升级为"**回判**"，不一致即 fail-loud。
- **共享比对助手 `_value_matches()`**：精确 → 数值容差 → 去引号 → **数字 token 序列比对**，
  覆盖浮点显示差（0.35 vs 0.3499999940395355）与结构体导出格式差。

## 二、🔴 回读机制首战：抓到并修复一个真实假成功（含对 v3.0 报告的更正）

**v3.0 报告中的一条"通过"结论需要更正**：UMG 用例 `set ColorAndOpacity = (R=0.1,G=0.2,B=0.3,A=1.0)`
当时报告为成功——**实为假阳性**。真实情况：`ColorAndOpacity` 是 **FSlateColor**，上述"美术习惯格式"
会被 ImportText **静默接受但值根本不变**（回读恒为白色 `(1,1,1,1)`）。v3.0 时期没有回读机制，无从发现。

**修复（v3.1）**：自适应格式重试——回读发现回读文本含 `SpecifiedColor=` 且请求未包装时，
自动以 `(SpecifiedColor=(...))` 重试并再次回读确认；成功则返回体 `note` 透明记录。

**实测证据**（UE5.1.1 活体）：
```
请求  : (R=0.1,G=0.2,B=0.3,A=1.0)
应用值: (SpecifiedColor=(R=0.1,G=0.2,B=0.3,A=1.0))     ← 自适应包装
回读  : (SpecifiedColor=(R=0.100000,G=0.200000,B=0.300000,A=1.000000))
结果  : success=true · verified=true · note="FSlateColor 包装格式自适应…"
```

**教训归档**：这是本项目"返回值说谎"缺陷家族的又一实例（哑类型 ImportText 静默接受不生效）；
回读比对是对该家族的系统性解法——**v3.1 起，所有含回读的写操作都不再可能静默失败**。

## 三、5.8 桥编译工具链结论（实测排定，取代此前"需 14.50+"的粗略表述）

| 工具链 | 结果 |
|:--|:--|
| MSVC 14.29（本机 VS2019） | ❌ 低于 5.8 引擎下限（`static_assert(_MSC_VER >= 1938)`） |
| MSVC **14.38**（v3.1 期间实装验证） | ❌ 引擎 `ContainerAllocationPolicies.h` 报 **C7539**（严格一致性错误）→ 5.8 实际需要更新的编译器 |
| MSVC 14.40–14.43 | ❌ 被 5.8 UBT **明令封禁**（本机 14.42 即在列） |
| **MSVC 14.44+（Epic 建议 14.50.35717）** | ✅ **可行区间** |

**安装命令**（需管理员）：
```cmd
"C:\Program Files (x86)\Microsoft Visual Studio\Installer\setup.exe" modify ^
  --installPath "<你的 VS2022 安装路径>" ^
  --add Microsoft.VisualStudio.Component.VC.14.44.17.14.x86.x64 --quiet --norestart
```
装好后：`cd bridge\BlueprintPythonBridge\Source` → `build_for_engine.bat "<UE5.8 引擎目录>"`。
