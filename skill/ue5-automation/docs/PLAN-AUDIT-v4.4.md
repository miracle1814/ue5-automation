## 二、利害得失（按"竞争力"标尺）

### 我们的真实资产（必须守住，不再改动）
1. **编译诊断闭环**：中文双变体提取 + 收敛判据分离 + 日志刷盘重读 —— 双引擎真机 2 轮收敛
2. **可信层**：`verified`/`compiled` 硬信号 + 未验证徽章 + fail-loud 全族
3. **可交付层**：交付物三要素 + 用户视角验证步骤（**竞品都没有**）
4. **轻量**：无 Electron 桌面壳，寄生任意 AI 客户端（Claude/Cursor/ZCode）
5. **上手**：一键部署 + 25 项自检 + 移植包
6. **上下文经济**：16 核心工具（132 token/工具均值），低于调研建议的 23 阈值

### 与竞品的利害对照

| 竞品 | 它的利 | 它的害 | 我们的应对 |
|---|---|---|---|
| **UEBox**（100+ 工具，Electron） | 能力全、桌面体验完整、5.0–5.8 | 重（Electron + 多模型适配）；作者自认"蓝图仍会出错""操作不安全" | **不追数量/壳**；攻它两个软肋（诊断更稳 + 可撤销/确认） |
| **VibeUE**（890 工具，官方注册） | 官方背书、性能剖析、undo | 仅 5.8+；依赖官方 MCP | 我们覆盖 5.1+5.8；**不追工具数** |
| **EngineWire**（974★，400+） | 能力广、原生插件 | 工具极多 → 选择成本高 | 我们 16 核心 + 84 命令透传 |
| **UnrealClaude**（950★） | 编辑器内聊天、600★ | 5.7 专用、需自编译 | 我们双版本预编译 + 一键部署 |
| 通用 MCP 教训 | — | 工具 >23 准确率暴跌；上下文 72% 被吃 | **已用 16 核心应对** |

### 得失结论
- **得（本轮）**：补上"不丢数据（A）、不被死循环拖死（B）、不误删（D）"三条实用底线 + 上手最后一道摩擦（S5）→ 从"能用"到"敢用"。
- **失（延后）**：撤销（C）与结构化诊断（F）延后 —— 前者需 C++ 事务栈，后者需双引擎重编，都是"正确但重"的活，不在本轮硬塞。
- **不做（守住简洁与边界）**：diff、提示词面板、性能剖析、工具数量、跨平台、完成提醒、流水人话化。

## 三、本轮实操顺序（按 ROI）

1. **A 保存闭环**（0.5d 量级）：`task_end` 自动保存本任务触碰的资产（`only_if_is_dirty`）+ 明确报告
2. **B 死循环保护**（0.5d 量级）：同 tool+参数连续失败 2 次（编译类放宽 5 次）拦截
3. **D 高危确认**（0.5d 量级）：`delete_asset`/`delete_node`/`unpin_console_refs`/`apply_graph{replace:true}` 需 `confirm=true`
4. **S5 客户端接入**（0.3d）：面板「接入 AI」生成 Claude Desktop / Cursor / ZCode 配置片段
5. **简洁化**（0.2d）：删调试图表、统一错误文案给「下一步」
6. 测试 + 真机验证 + 提交

预期总成本：~2 人天（与 v4.2 的 P0 前两项相当，但覆盖了 A/B/D/S5）。

## 四、验收标准（本轮）

- A：改图不保存就 `task_end` → 返回体含 `auto_saved` 字段，且重开编辑器资产仍在
- B：对同一不存在的蓝图连续 `compile_and_diagnose` 3 次 → 第 3 次被拦截并提示换方法
- D：`delete_asset` 不带 `confirm` → 拒绝并说明；带 `confirm:true` → 执行
- S5：面板能生成三种客户端配置，复制即用
- 简洁：调试视图少一张图，页面体积下降
- 基线：672+ passed / 0 failed
