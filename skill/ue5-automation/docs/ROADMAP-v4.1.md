# ue5-automation v4.1 优化计划（三面评估 + 竞品对标 + ROI）

> 日期：2026-10-27 · 基线：v4.0（672 passed，全流程 19/19 PASS / 1.7s）
> 方法：今日真机全流程实测 + 全网竞品调研 + AI Agent UX 最佳实践对标
> 结论先行：**执行逻辑缺"可撤销/可审批"，上手缺"客户端一键接入"，体验缺"结构 diff 与失败指引"**。
> 不建议追工具数量（竞品 890+，我们 84），应把力气放在"可信与可撤销"这条差异化上。

## 二、三面评估

### 2.1 整体执行逻辑

**现状（做得对的）**
- 链路完整：原话 → 意图 → 计划 → 命令 → 结果 → 交付 → 复盘，七段都有落点；
- fail-loud 纪律贯穿（类型不可连、图非空、标题歧义、PIE 未运行都明确拒绝）；
- 结论与手段分离（`verified`/`compiled` 是硬信号，`errors` 是日志窗口）；
- 事务内回滚（`apply_graph` 失败 clean=true）。

**缺口（按痛感排序）**

| # | 缺口 | 实测/证据 | 影响 |
|---|---|---|---|
| L1 | **没有任务级撤销** | 写完图后只能手动在 UE 里 Ctrl+Z（且跨操作不可靠）；任务的"回滚"只有单次 apply 的事务内 | 用户不敢让 agent 动重要蓝图；出错要手工复原 |
| L2 | **没有审批门** | `delete_asset`、`apply_graph replace=true` 等破坏性操作由 agent 直接执行 | 企业采用的最大心理障碍；调研显示 29% 企业要求人工确认才能执行 |
| L3 | **修复策略靠 agent 推理** | 诊断只给错误 + 规则库 fix_hint；"下一步调什么命令"由模型自由发挥 | 同一错误不同 agent 修法不一，收敛轮次不稳 |
| L4 | **无图结构 diff** | 用户只能看截图对比，看不到"加了哪个节点、连了哪条线" | "改了什么"仍要靠人打开蓝图核对 |
| L5 | **进度依赖 agent 上报** | hint 归位是启发式；agent 不调 `task_step` 时步骤停在进行中（靠自动封口兜底） | 步骤完成度可能失真 |

### 2.2 用户上手难度

**现状（做得对的）**
- 移植包：`install.bat` 三步、自动读 EngineAssociation 选 DLL、备份、写 `.uproject`；
- `check_env.py` 25 项自检，FAIL 数即退出码；
- README-新机测试：3 步部署 + 6 项验收 + 7 个 FAQ + 记录表；
- 实测：解压到全新目录 → 部署 → 自检 25/25 PASS。

**缺口**

| # | 缺口 | 影响 |
|---|---|---|
| U1 | **AI 客户端接入仍需手配** | 用户拿到包后还要自己写 MCP 配置（HTTP 地址/token/stdio 代理），非技术用户会卡住 |
| U2 | **不知道该对 AI 说什么** | 首次任务缺少"可直接复制的提示词"，用户容易问出工具不支持的需求 |
| U3 | **概念术语门槛** | "整图写入/读回验证/未验证徽章"等术语没有一处面向新手的解释页 |
| U4 | 5.2–5.7 需自编译 | 已知限制（计划外） |

### 2.3 工具主观体验（管理端）

**现状（做得对的）**
- 5 段阶段轨道 + 独立卡片，功能区清晰；
- 你的原话 vs 我理解成，开工前可纠偏；
- 命令流水含"UE 内动作"人话解释；
- 交付物三要素 + 分步验证；
- 数据签名比较（不打断展开状态）、1s 轮询、白底主题。

**缺口**

| # | 缺口 | 影响 |
|---|---|---|
| X1 | **命令流水参数仍是技术味** | 显示 `graph=EventGraph nodes=2 edges=1`，普通用户读不出"改了哪两个节点" |
| X2 | **失败后没有"下一步"** | 失败卡片只有原因，没有"建议怎么办"（重试/换方法/找人） |
| X3 | **长任务无完成提醒** | 面板不会主动告知"已完成"，用户要一直盯 |
| X4 | **无前后截图自动配对提示** | 有 evidence.pair 能力，但 agent 少用；面板不提示"可对比" |
| X5 | 无暗色模式/无移动端 | 非核心（用户已确认白底优先） |

## 三、竞品对标（2026-10 调研）

| 维度 | 本工具 v4.0 | VibeUE | UnrealClaude | 官方 MCP（5.8+） |
|---|---|---|---|---|
| 工具数量 | **84 命令 / 31 MCP 工具** | **890+ 工具 / 30 toolsets** | 少量（视口+actor） | 原生 toolsets |
| 引擎覆盖 | **5.1–5.8** | 仅 5.8+ | 5.8+ | 仅 5.8+ |
| 接入方式 | 自建 HTTP 桥（5.1 也能用） | 挂官方 ToolsetRegistry | 插件 | 引擎内建 |
| 撤销/回滚 | ❌ 仅单次事务内 | ✅ **editor undo/redo 事务** | ❓ | 部分 |
| 性能剖析 | ❌ | ✅ **CPU/GPU bound + Insights trace** | ❌ | ❌ |
| 编译诊断自愈 | ✅ **中文日志 + 收敛** | 有 batch graph builder，无同等诊断闭环 | ❌ | ❌ |
| 可验证/可审计 | ✅ **verified/compiled/交付物/未验证徽章** | ❌ 无任务级审计 | ❌ | ❌ |
| 跨平台 | ❌ 仅 Win | ✅ Win/Linux/mac | ❓ | ✅ |
| 上手（新机） | ✅ 一键部署 + 25 项自检 | 装插件+配官方 MCP | 装插件 | 需 5.8 |
| 社区影响力 | 0★ | 高 | ~600★ | 官方 |

**取长补短结论**
1. **不追数量**：890 工具是资源战，我们单人维护追不上，也没必要（用户 90% 需求集中在建图/读图/诊断/截图）。
2. **必须补"撤销 + 审批"**：这是调研里所有 agent UX 来源共同的第一优先级（supervision > reporting），也是竞品里 VibeUE 唯一让我们眼馋的能力。
3. **把"可信"做成标签**：审计/交付物/未验证徽章目前是我们的独占项——竞品没有任务级审计；把它做成对外卖点（而不是功能列表里一行字）。
4. **借力官方 MCP**：5.8 上允许与官方 toolsets 共存（我们已能共存），把 890 工具的生态当"外部能力"，自己专注诊断+验证+审计。

## 四、建议清单（可行性 × ROI）

ROI 口径：**年化节省/创造的用户时间（或降低的失败率）÷ 工程人天**。
假设：活跃用户 20 人（团队+外部试用），每人每周 5 个任务。

| # | 建议 | 可行性 | 工程成本 | 预估收益 | ROI |
|---|---|---|---|---|---|
| **S1** | **任务级撤销**：任务开始时对涉及资产打快照（复制 .uasset 到 Saved/Backup），面板一键"回滚本任务" | 高（文件级快照最稳，无需 C++） | 2 人天 | 出错恢复从 10-30 分钟降到 10 秒；**敢让 agent 动重要资产**（使用意愿↑） | ★★★★★ |
| **S2** | **高危操作审批门**：`delete_asset` / `apply_graph replace=true` / 多资产批量 → 面板弹出"待批准"卡片，用户点允许/拒绝（HTTP 阻塞等待，超时默认拒绝） | 中（需前端交互 + 桥端阻塞队列，但只读面板要破例引入一条写路由） | 3 人天 | 企业采用门槛↓；误删风险→0 | ★★★★★ |
| **S3** | **失败下一步建议**：诊断失败时按错误类型给「建议命令序列」（如类型不匹配 → 断开该引脚 + 加转换节点） | 高（规则库扩字段，已有 19 条模式） | 1.5 人天 | 收敛轮次 2→1.3；用户不再看到"失败了但不知道怎么办" | ★★★★☆ |
| **S4** | **图结构 diff**：任务结束用 read_nodes 前后快照做节点/连线级 diff，面板以"＋3 节点 −1 连线"展示 | 中（需要快照存储 + diff 算法，纯 Python） | 3 人天 | "改了什么"从"打开蓝图核对"变成"看一行摘要" | ★★★★☆ |
| **S5** | **AI 客户端一键接入**：生成 Claude Desktop / Cursor / ZCode 的 MCP 配置片段（含 token），一键复制/写文件 | 高（模板 + token 读取） | 0.5 人天 | 上手从"查文档配置"变成"复制一段" | ★★★★☆ |
| **S6** | **提示词模板库**：10 个可直接复制的需求说法（建功能/改图/排查/批量改参数…），含"这样问效果最好" | 高（纯文档+面板入口） | 0.5 人天 | 首次任务成功率↑（减少"问错"） | ★★★★☆ |
| **S7** | **完成提醒**：任务结束时浏览器 Notification + 标题闪烁 + 可选声音 | 高（前端 API） | 0.3 人天 | 长任务不必盯屏 | ★★★☆☆ |
| **S8** | **命令流水人话化**：把 `nodes=2 edges=1` 换成"新增 2 个节点、1 条连线（重叠→打印）" | 中（需要从 graph_spec 提取节点名/目标） | 1 人天 | 阅读门槛↓ | ★★★☆☆ |
| **S9** | **自动推进步骤**：agent 不上报时按 hint 匹配自动标 done（当该步骤的命令全部成功） | 中（规则化，但可能与 agent 意图冲突） | 1.5 人天 | 步骤完成度更准 | ★★★☆☆ |
| **S10** | **性能剖析**（对标 VibeUE）：帧时间 + CPU/GPU bound 判定 | 中高（需 C++ 或 stat 命令解析） | 5 人天 | 打开新场景（性能优化），但与当前定位弱相关 | ★★☆☆☆ |
| **S11** | **工具数量扩张**（追 890） | 低（长期） | 30+ 人天 | 边际收益递减 | ★☆☆☆☆ |
| **S12** | **跨平台**（Linux/mac 编译） | 低（需 CI + 三平台测试） | 10 人天 | 用户群窄 | ★☆☆☆☆ |

**可行性风险提示**
- S2 需要打破"面板永久只读"铁律（新增一条 POST 审批路由）——建议用**独立端口/独立前缀**
  （`/approve/*`）隔离，只写"批准状态"，不碰资产，风险可控。
- S1 文件快照对大资产（>500MB）有开销 → 只快照任务涉及资产，且上限 200MB，超限降级为"提示用户手动备份"。

## 五、分阶段计划

### P0 —— 本周（3.5 人天）：让工具"敢用"
| 项 | 交付 | 验收标准 |
|---|---|---|
| S1 任务级撤销 | `task_begin` 自动快照涉及资产；面板「回滚本任务」；`/ui/api/rollback` | 改坏一个蓝图 → 一键回滚 → 编译器打开与任务前一致（diff 为空） |
| S2 高危审批 | 三条高危命令挂 `pending_approval`；面板批准/拒绝卡片；超时 60s 默认拒绝 | 删资产前弹卡；拒绝后命令不执行且返回明确错误 |
| S3 失败下一步建议 | 诊断返回 `suggested_next`（命令序列）；面板显示 | 类型错误 → 建议"断开引脚 + 加转换"可直接点复制 |

### P1 —— 两周（4 人天）：让工具"好用"
| 项 | 交付 | 验收标准 |
|---|---|---|
| S5 客户端一键接入 | 面板「接入 AI」页：生成 3 种客户端配置 | 新机复制配置 → 5 分钟内 agent 能调通 |
| S6 提示词模板库 | 面板「怎么问」抽屉 + docs/prompts.md | 10 条模板，首次任务成功率可测 |
| S8 命令流水人话化 | 流水显示"新增 2 节点、1 连线（重叠→打印）" | 非技术用户能读懂每条流水 |
| S7 完成提醒 | 浏览器通知 + 标题闪烁 | 任务结束 3 秒内有提示 |

### P2 —— 一个月（8 人天）：形成差异化壁垒
| 项 | 交付 | 验收标准 |
|---|---|---|
| S4 图结构 diff | 前后 read_nodes 快照 + 节点/连线 diff | 面板显示"+3 节点 −1 连线"，带节点名 |
| S9 自动推进步骤 | 按 hint + 命令成功率自动标 done | agent 只上报 begin/end 时步骤完成度仍准确 |
| 审计包导出增强 | 任务 zip（交付物清单 + 命令流水 + 前后截图 + diff） | 一键导出可交给客户的验收包 |

### 不做（明确排除）
- S11 工具数量军备（890+）：不是我们的战场，改用"与官方 MCP 共存 + 专注诊断验证"策略；
- S12 跨平台、S10 性能剖析：与"蓝图自动化 + 可信审计"定位弱相关，等有真实需求再做。

---

## 六、一句话结论

**我们已经在"可信"这条轴上领先（审计/交付物/未验证徽章竞品都没有），但缺"可撤销"和"可审批"——这两项是用户敢把重要资产交给 AI 的前提。**
P0 三项（撤销/审批/失败指引，3.5 人天）投入产出比最高，建议立刻做；P1 解决上手摩擦；P2 建立不可复制的差异化（结构 diff + 验收包）。
