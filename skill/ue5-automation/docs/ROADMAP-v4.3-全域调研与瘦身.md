## 二、差异点采纳矩阵（逐个过筛，不照搬）

判定三问：① 对"改蓝图→验证→交付"是否必要？② 我们现有架构能否低成本实现？③ 是否是竞品已验证的刚需（而非厂商宣传）？

### ✅ 采纳（有实证刚需）

| 差异点 | 来源 | 为什么采纳 | 成本 |
|---|---|---|---|
| **保存闭环检查**（改动没存就警告） | UEBox | 我们今天真实踩坑（BP_Door 重启丢失，工具无提示）；数据丢失级痛点 | 0.5 人天 |
| **死循环保护**（同参失败 2 次拦截） | UEBox loopBreaker | agent 反复撞墙烧钱且破坏信任；规则极简 | 1 人天 |
| **任务级撤销**（快照/事务） | UEBox 独立事务栈 · VibeUE undo checkpoint | 用户敢让 AI 动重要资产的前提 | 2 人天 |
| **高危审批（两档）** | UEBox 三档 · 通用 agent UX 第一优先级 | 误删风险归零；企业采用门槛 | 2.5 人天 |
| **资产锁提示** | UEBox assetLock | 用户与 AI 同时改同一资产会互相覆盖 | 1 人天 |
| **C++ 结构化编译诊断** | UEBox `FCompilerResultsLog` | 我们从日志正则解析，精度低一档；中文引擎仍是我们更强 | 3 人天 |
| **核心/扩展工具分级** | StraySpark 22 工具前门 · MCP 经济学 | **我们有实证：31 工具里 19 个 4 天未使用、占 44% token** | **0.5 人天（已做）** |
| **结果大小硬上限** | UnityMCP-VRC 25K 分页 | 防止 `read_nodes` 等大结果灌爆上下文 | 0.5 人天 |
| **技能优先于工具**（按需读） | 中文 Unity 实战 | SKILL.md 精简 + 分级引用，减少 agent 常驻成本 | 1 人天 |

### ❌ 不采纳（明确理由）

| 差异点 | 来源 | 不采纳理由 |
|---|---|---|
| 工具数量军备（100+/400+/890+） | UEBox/ChiR24/VibeUE | 与"选择准确率↓、上下文↑"直接冲突；我们是 13 核心 + 84 命令透传，覆盖 90% 场景 |
| Electron 桌面壳 + 70 家模型接入 | UEBox | 我们寄生在用户已有的 AI 客户端，轻量；自建壳=重资产、要维护更新与多模型适配 |
| 试玩机器人/按键测试 | UEBox | 场景窄（需要具体游戏逻辑），我们 PIE 截图已够验证 |
| 文生图→图生 3D、动画重定向、Substrate 材质 | UEBox | 越出"蓝图自动化"边界，属于美术/建模工具 |
| C++ 源码热重载 | UEBox | 高风险（要关用户编辑器），且我们定位不含 C++ 编辑 |
| PIE 多帧采样（frame_times） | UEBox | 单帧够用；多帧是"测行为时序"的专门需求 |
| 性能剖析（CPU/GPU bound、Insights） | VibeUE | 定位不相关，是性能工具不是蓝图工具 |
| 视觉角色兜底（visionRouting） | UEBox | 依赖多模型路由；我们默认假设客户端模型有视觉能力 |
| 崩溃监视 + 自动重开编辑器 | UEBox | HTTP 桥天然无状态，编辑器重启后宿主只需重连；监视复杂度高 |
| 跨平台（Linux/mac） | VibeUE | UE 蓝图自动化的用户 99% 在 Windows |
| 图结构 diff（节点级） | v4.1 自拟 | 用户要的是"编译通过 + 截图对"，节点级 diff 是炫技；截图对比已覆盖 |
| 提示词模板面板 | v4.1 自拟 | 纯文档可解决，不必进产品 |
| 更多动效/装饰 | v4.1 自拟 | 主观加分有限，停止投入 |

## 四、结论：我们该打的三场仗

1. **比 UEBox 更稳的"改到通过"**：F（C++ 结构化诊断）+ B（死循环保护）+ A（保存闭环）
   —— 直接打它公开承认的软肋「蓝图仍会出错」。
2. **比所有竞品更敢用**：C（撤销）+ D（审批）+ E（资产锁）+ 已有未验证徽章
   —— 打另一个软肋「Agent 操作不安全」。通用 agent UX 调研也把"审批 + 撤销"列为第一优先级。
3. **比所有人更省上下文**：13 核心工具 + 84 命令透传（已做）+ SKILL 分层（待做）
   —— 因为 2026 的共识是"工具目录是硬成本"，而多数竞品还在堆数量。

**不要打的仗**：工具数量、桌面壳、美术能力、跨平台、性能剖析。
